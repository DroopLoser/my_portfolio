Problem

Drug discovery needs candidate molecules that are both chemically valid and close to a target property. Generating them is one problem; serving them through a usable product is another.

Approach

A VAE + GNN model pipeline, trained on 50,000+ molecules from ZINC250k, wrapped in an Agentic AI platform with a FastAPI backend and a Next.js/React frontend.

Engineering decisions

  • SELFIES as the molecule representation.
  • Async request processing to reduce API latency.
  • Frontend, backend and model serving kept decoupled, so each layer can scale on its own.

Problem

A general-purpose model answers well but doesn't hold a persona. The goal was dialogue that stays in character across many traits.

Approach

Fine-tune LLaMA-3-8B with LoRA on a 4-bit quantized model, using a dataset built for this project. An end-to-end training and evaluation pipeline in Hugging Face and PyTorch.

Engineering decisions

  • Quantize first, then train adapters, so an 8B model stays practical to tune.
  • Trainable parameters cut to 20.9M of 8.05B.
  • Dataset designed around 70+ traits instead of reusing a generic one.

How I think

I like to own the whole path. The molecule project runs from dataset to browser: model, API, interface. Each layer stays separate enough to change without breaking the others.

I'd rather understand the mechanism than lean on an abstraction. The digit classifier exists because I wanted to write backpropagation myself. The LoRA project came from asking how little of a model you actually need to change.

A model is only useful once someone can use it. That is why the work pairs PyTorch with FastAPI and Next.js.

Experiments should end in numbers: 85% valid generation, 92% on MNIST, 20.9M trainable parameters. I build, measure, then decide what to do next.
